      Analyse a real email

      Drop an .eml email, an HTML file or a QR-code image anywhere on the page, or paste raw email source or a QR screenshot into the box below. You get the real headers, real link destinations, attachment names and any QR-code links.

      How do I get the email file from my inbox?
      Gmail
      Open the email → ⋮ More (top right of the message) → Download message. Or Show original → Copy to clipboard and paste it into the box below.
      Outlook on the web / new Outlook
      Open the email → ⋯ → Save / Download (saves an .eml file).
      Classic Outlook for Windows
      Drag-and-drop saves a .msg file, which isn't supported. Open the email → File → Properties, copy the Internet headers, and paste them above the message text in the box below.
      Apple Mail
      Select the email → File → Save As → Format: Raw Message Source, or drag it to your desktop.
      Thunderbird
      Open the email → ⋯ / File → Save As → File (.eml).
      Yahoo Mail
      Open the email → ⋯ → View raw message, copy everything and paste it below.

      Why not just log in to your mailbox? A web page asking for your email password is exactly what phishing looks like. A safe direct connection needs OAuth sign-in and a server, which this private, server-free version deliberately avoids. Opening a saved email is completely safe here: attachments are never opened, and links are never visited.

      What this checks

      • Language: urgency, threats, requests for passwords, MFA codes, payments, gift cards and bank-detail changes
      • Links: look-alike domains, shortened links, raw IP addresses, "@" tricks, hidden redirect destinations and link text that lies about its destination
      • QR codes: links hidden in QR images (quishing), read on this device and never opened
      • Look-alike letters: Unicode homographs such as a Cyrillic "а" in "pаypal.com", plus invisible characters
      • HTML tricks: fill-in forms, automatic redirects, hidden text and HTML attachments
      • Attachments: executables, double extensions, macro documents and "Enable Content" requests
      • Sender: SPF/DKIM/DMARC failures, Reply-To mismatches and fake display names
      • Voice calls: impersonated banks and IT staff, "safe accounts" and remote-access requests

      Privacy & how it works

      Your email never leaves this page

      All analysis is done by JavaScript running inside your browser tab. There is no server, no AI service, no analytics and no tracking. The page includes a Content Security Policy that forbids it from connecting to any server at all, so even a bug could not upload your text.

      You can check this yourself: open your browser's developer tools (F12), go to the Network tab, and click Analyse. No new requests appear. You can also disconnect from the internet and the analyser keeps working.

      What is stored

      If you leave the checkbox ticked, the analyser saves a small summary of each analysis in your browser's local storage: the date, the score, and the names of the warning signs. It never saves the message itself. Challenge answers and training progress are stored the same way. Use the button below to delete all of it.

      How the score works

      Each warning sign has a weight that reflects how strongly it predicts phishing. A password request counts far more than a generic greeting. Signs that are much more dangerous together, such as a credential request plus a fake link, add a bonus.

      Evidence is counted once. Several rules can fire on the same evidence, so the score counts independent evidence, not rule hits. Words already matched by a stronger rule are not counted again. Each link and each file counts once: its strongest problem in full, other problems with the same link or file add 25%, and extra suspicious links or files add half. Related checks, such as SPF, DKIM and DMARC or urgency and threats, add a reduced share after the strongest one. Words inside links and email addresses are not treated as message text. The risk score (0–100) is then shared out between the counted warning signs in proportion to their evidence, so the numbers shown next to the reasons always add up to exactly the risk score.

      The total is converted to a 0–100 scale: Low (0–19), Medium (20–44), High (45–69), Critical (70–100).

      QR codes, HTML and look-alike letters

      QR codes are read from images on your own device, using the browser's built-in reader where available or the small open-source jsQR reader bundled with this site (Apache-2.0 licence). The decoded link is checked like any other link and is never opened. HTML is only ever read as text: forms, redirects, frames and hidden text are reported, but nothing in it is run or loaded. Look-alike letters are found by decoding international domain names and comparing each letter with the English letter it imitates. A domain is not flagged just for using another language's letters, only for mixing alphabets or imitating a brand.

      Limits

      This is a rule-based teaching tool, not a security product. It can miss well-crafted attacks and can flag legitimate messages. It never visits links, so it cannot see what a website actually contains. A low score is not proof that a message is safe. When in doubt, verify through a channel you trust and report it to your security team.
